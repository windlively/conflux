# Release 更新说明

发布流水线建好 Release 后，会用 `docs/releases/<tag>.md` 的内容覆盖正文（见 `.github/workflows/release.yml` 的 `notes` 作业）。文件名必须与 tag 完全一致，例如 tag `v0.3.0` 对应 `v0.3.0.md`。

写法：

- 一节一个主题，用 `###` 小标题，不写 `#`／`##`（Release 标题本身已经带了版本号）。
- 写用户能感知的变化，不按提交逐条罗列。
- 正文只有更新内容；安装说明与已知限制放在仓库根目录的 README 里，别写进来。

打 tag 前记得先把对应版本的文件提交上去，否则正文会停在流水线里的兜底文案。
